# Видео-риллс PlataPay

Набор для производства вертикальных видео 1080×1920 из логотипов, которые уже
лежат в корне репозитория. PlataPay оплачивает зарубежные AI-сервисы и другие
подписки — ролики про это. Сцены собираются в HTML/CSS, рендерятся кадр за
кадром через headless Chromium и кодируются в MP4, готовый к загрузке в
Instagram Reels, TikTok, YouTube Shorts и VK Клипы.

Никакого монтажа руками: текст риллса — это JSON-файл, который правится за минуту.

## Быстрый старт

```bash
cd reels
npm install                 # playwright-core + статический ffmpeg
npx playwright install chromium   # один раз, если Chromium ещё не стоит
npm run render              # отрендерит все риллсы в reels/out/
```

Посмотреть и прокрутить до рендера:

```bash
npm run preview             # откройте http://127.0.0.1:4321/reels/preview.html
```

Отрендерить один риллс:

```bash
npm run render -- --project=card-declined
```

## Что получается на выходе

Для каждого проекта в `reels/out/` появляется (папка лежит в репозитории —
там всегда последняя собранная версия роликов):

| файл | зачем |
| --- | --- |
| `<имя>.mp4` | само видео: H.264 high, 1080×1920, 30 fps, `yuv420p`, `+faststart`, тихая AAC-дорожка (её требуют некоторые загрузчики) |
| `<имя>-cover.jpg` | кадр для обложки в ленте |
| `<имя>.txt` | готовый текст поста с хештегами |

Музыку намеренно не вшиваем: у соцсетей свои лицензированные треки, и ролик с
нативным звуком платформы получает больше охвата. Накладывайте музыку уже в
приложении при публикации. А вот закадровый голос вшивается — см. «Озвучка».

## Готовые риллсы

| проект | о чём | длина |
| --- | --- | --- |
| `ai-payments` | «карта не берёт подписку на ИИ» → витрина нейросетей | ~12.8 с |
| `card-declined` | боль «карта отклонена» → было/стало → переписка | ~15.2 с |
| `ai-stack-top5` | топ-5 AI-подписок, которые просят чаще всего | ~12.5 с |
| `how-it-works` | три шага: написал → счёт → пользуешься | ~14.7 с |

Тексты — рабочая версия, не истина в последней инстанции. Цифра 99 в счётчике
взята из числа логотипов в репозитории; «чаще всего» в топ-5 — предположение.
Сверьте с тем, как на самом деле, прежде чем публиковать.

## Как сделать свой риллс

Создайте `reels/projects/мой-риллс.json`:

```json
{
  "id": "мой-риллс",
  "fps": 30,
  "scenes": [
    { "type": "hook", "duration": 2.6, "kicker": "just platapay",
      "title": "Заголовок|во всю *ширину*", "sub": "Пояснение помельче." },
    { "type": "cta", "duration": 3.2, "title": "Напиши — и *оплатим*" }
  ],
  "post": { "caption": "Текст поста", "hashtags": ["#подписки"] }
}
```

Больше ничего делать не нужно: и предпросмотр, и рендер видят все проекты в
папке сами.

Кроме `scenes` проект понимает ещё несколько необязательных полей:

* `fps` — частота кадров, по умолчанию 30;
* `posterAt` — секунда, с которой снимается обложка (по умолчанию 1.2);
* `progressBar: true` — тонкая полоска прогресса по низу кадра;
* `theme` — переопределение цветов из `brand.json` для этого ролика.

### Разметка текста

В любом заголовке работают три символа:

* `*слово*` — красим акцентным цветом;
* `~слово~` — приглушаем (для «было»);
* `|` — перенос строки.

### Сцены

| `type` | поля | что показывает |
| --- | --- | --- |
| `hook` | `kicker`, `title`, `sub`, `size` (`small`/`tiny`) | первый кадр: крючок, ради которого не листают дальше |
| `ticker` | `rows`, `perRow`, `speed`, `title`, `logos` | бесконечная лента логотипов как подложка |
| `logoGrid` | `cols`, `rows`, `count`, `plus`, `caption`, `logos` | сетка логотипов + счётчик, набегающий до `count` (`plus: false` убирает «+», если число точное) |
| `list` | `title`, `items[{logo,name,note}]` | нумерованный топ сервисов |
| `steps` | `title`, `items[{head,desc}]` | пошаговая схема |
| `chat` | `title`, `step`, `messages[{from,text,small}]` | переписка; `from` = `them` (клиент) или `me` (мы) |
| `beforeAfter` | `title`, `before`/`after` `{tag,line,hint}` | сравнение «сам» / «через нас» |
| `cta` | `title`, `sub`, `handle` | финальная карточка с лого и ником |

У каждой сцены есть `duration` (секунды), опционально `fadeIn` и `fadeOut`.

### Логотипы

`"logos": ["Spotify", "GPT", "Claude"]` — имена берутся из `src/catalog.json`,
он же имена файлов в корне репозитория без расширения. Если список не указать,
сцена возьмёт логотипы из каталога сама (порядок детерминированный).

Незнакомое имя логотипа останавливает рендер с ошибкой — так риллс не уедет в
публикацию с дыркой.

### Новые логотипы

Положите PNG с прозрачным фоном в корень репозитория и пересоберите каталог:

```bash
npm run catalog             # нужен python3 с Pillow
```

Скрипт сам посчитает рамку непрозрачных пикселей (логотипы выравниваются по
оптическому размеру, а не по краям файла), вытащит фирменный цвет для свечения
и среднюю яркость — по ней плитка под логотипом становится светлой или тёмной,
чтобы чёрные монохромные знаки не пропадали на фоне.

### Брендинг

`reels/brand.json` — имя, ник и цвета.

```json
{ "name": "PlataPay", "handle": "",
  "theme": { "accent": "#2BE08C", "accent-2": "#7A5CFF" } }
```

`handle` пустой: впишите туда реальный ник или адрес — телеграм, сайт, что угодно.
Пока он пустой, последний кадр обходится без плашки с контактом.
`prefix` можно добавить, если перед названием должно стоять слово.

Любой проект может переопределить `theme` — удобно, чтобы у рубрики был свой цвет.

## Озвучка

Реплики диктора живут рядом со сценами — у каждой сцены может быть поле `voice`:

```json
{ "type": "hook", "duration": 2.6, "title": "Заголовок",
  "voice": "Реплика, которую произносит диктор." }
```

Если в сцене две фразы, задайте их со смещением от начала сцены:

```json
"voice": [
  { "at": 0.2, "text": "Первая фраза." },
  { "at": 2.6, "text": "Вторая." }
]
```

Текст озвучки специально отделён от текста на экране. На экране — «ChatGPT
Plus», в озвучке — «Чат-джи-пи-ти Плюс»: синтез читает латиницу плохо, а живой
диктор — не так, как хочется. Заодно голос может говорить не то же самое, что
написано, а дополнять картинку.

### Проверить тайминги до записи

```bash
npm run voice -- --project=<проект> --check
```

Печатает каждую реплику, сколько секунд она примерно займёт и сколько секунд
даёт сцена. Реплики, которые не влезают, помечены — их надо укоротить или
растянуть сцену. Ничего не синтезируется и не тратится.

Заодно кладёт `reels/voice/<проект>/script.txt` — пронумерованный лист, по
которому диктор пишет реплики: номер файла, текст, и сколько секунд на него есть.

### Откуда берётся голос

`--provider` (или переменная `VOICE_PROVIDER`), по умолчанию `file`:

| провайдер | что нужно | когда |
| --- | --- | --- |
| `file` | файлы в `reels/voice/<проект>/01.wav`, `02.wav`… | живой диктор — всегда лучше синтеза |
| `heygen` | `HEYGEN_API_KEY` | если HeyGen уже оплачен |
| `elevenlabs` | `ELEVENLABS_API_KEY` | сильный русский синтез |
| `openai` | `OPENAI_API_KEY` | попроще и подешевле |

Весь путь до озвученных роликов — четыре строки:

```bash
export HEYGEN_API_KEY=...
npm run voice -- --voices --provider=heygen --lang=ru   # выбрать голос
export VOICE_PROVIDER=heygen VOICE_ID=<id из списка>
npm run render                                          # ролики уже с голосом
```

Дефолтного русского голоса нет ни у одного провайдера, поэтому id обязателен.
Файлы при этом править не нужно: настройки берутся из переменных окружения,
из проекта (`voiceSettings`) или из `brand.json` → `voice` — в таком порядке
приоритета. Если озвучивать регулярно, впишите провайдера и голос в `brand.json`
и забудьте про экспорт.

```bash
npm run render -- --no-voice        # собрать без голоса
```

### Без своей машины: прямо в GitHub

В репозитории лежит workflow `.github/workflows/reels.yml` — сборка идёт на
раннерах GitHub, ставить ничего не нужно. Один раз положите ключ в секреты
репозитория (Settings → Secrets and variables → Actions → New repository
secret), имя — `HEYGEN_API_KEY`.

Дальше вкладка Actions → «Риллсы» → Run workflow:

* `mode: voices` — печатает русские голоса прямо в отчёт о прогоне;
* `mode: render` + `voice_id` из этого списка — собирает ролики.

Готовые MP4, обложки и тексты постов падают в артефакты прогона (скачиваются
zip-архивом), а галочка `commit` дополнительно кладёт их обратно в ветку.

Отдельный шаг проверяет, что голос действительно записался: при сбое синтеза
рендер не падает, а кладёт тихую дорожку, поэтому workflow измеряет громкость
готового ролика и валит прогон, если он собрался немым.

Кнопка Run workflow появляется только когда файл workflow есть в ветке по
умолчанию — до слияния ветки её не будет видно.

HeyGen синтезирует через `POST /v3/voices/speech` (движок `starfish`) — это
отдельная ручка для чистого аудио, видео и аватары она не трогает. Скорость речи
задаётся в `voiceSettings.speed` (0.5–2.0), движок — в `voiceSettings.engine`.

Синтезированные реплики кэшируются в `reels/.voice-cache/` по тексту: правка
одной фразы не заставляет переозвучивать весь ролик.

Готовая дорожка выравнивается до −16 LUFS (к этому уровню соцсети и так приводят
речь) и вшивается в MP4 как AAC 160 kbps. Если реплика по факту оказалась длиннее
своей сцены, рендер об этом скажет, но ролик всё равно соберёт.

Настройки голоса — в проекте:

```json
"voiceSettings": { "provider": "elevenlabs", "voiceId": "...", "model": "eleven_multilingual_v2" }
```

## Что снять дальше

Сцены уже покрывают все ходовые форматы — под каждый из них ролик собирается за
пару минут правкой JSON:

* «Сколько стоит ChatGPT Plus в рублях сегодня» — `hook` + `list` с ценами;
* «5 сервисов, которые просят чаще всего на этой неделе» — `list`, меняется еженедельно;
* «Что делать, если списали, а подписка не активировалась» — `chat`;
* «Оплатили за 11 минут» — `chat` со временем в `small`;
* «Сервисы для монтажёров / дизайнеров / геймеров» — `logoGrid` со своим набором `logos`;
* «Было — стало» под конкретный сервис — `beforeAfter`.

Один заголовок = один ролик: под каждую рубрику лучше свой файл в `projects/`,
чтобы потом можно было пересобрать всю серию одной командой.

## Параметры рендера

```bash
node render.mjs --project=all --fps=30 --crf=18 --preset=slow --format=mp4
```

| флаг | по умолчанию | что делает |
| --- | --- | --- |
| `--project` | все | имя проекта, или несколько через запятую, или `all` |
| `--fps` | из проекта (30) | частота кадров |
| `--crf` | 18 | качество H.264: меньше — лучше и тяжелее |
| `--preset` | `slow` | пресет x264; `veryfast` для черновиков |
| `--format` | `mp4` | `mp4` (H.264) или `webm` (VP9) |
| `--no-audio` | — | не добавлять тихую звуковую дорожку |
| `--out` | `reels/out` | папка вывода |

Chromium берётся из `CHROMIUM_PATH`, иначе из стандартных путей Playwright.
ffmpeg — из пакета `ffmpeg-static`, либо из `FFMPEG_PATH`.

## Безопасные зоны

Интерфейс соцсети закрывает примерно 210 px сверху и 440 px снизу — весь текст
сцен живёт внутри этих отступов. Включите чекбокс в предпросмотре, чтобы увидеть
границы.

## Шрифт

Inter (SIL Open Font License 1.1) лежит в `assets/fonts/` вместе с текстом
лицензии — подтягивать его из сети при рендере не нужно, и кадры не зависят от
того, какие шрифты стоят на машине.

## Почему так собрано

Анимация — чистая функция времени: `REEL.seek(t)` рисует кадр для секунды `t`,
никаких CSS-переходов и `requestAnimationFrame`. Поэтому кадр не зависит ни от
скорости машины, ни от того, успел ли браузер отрисовать анимацию: пересборка
того же проекта даёт тот же ролик, а частоту кадров можно поднять до 60 fps —
движение просто станет плавнее, а не «поедет».
